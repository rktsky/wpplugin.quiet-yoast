Rocketsky – Quiet Yoast 1.2.0: interface contracts
Reviewed 2026-11-10

Scope

An independent plugin. No output buffering, provider method replacement,
filesystem changes to other packages, direct SQL, settings writes, licence
emulation, React/Redux manipulation or polling. A scoped standard DOM
MutationObserver maintains the displayed counter text only.
No runtime library dependencies beyond WordPress and the existing free Yoast.

WordPress contracts

plugins_loaded runs after active plugins have loaded. At priority 20 the loaded
Yoast edition is identified through its provider constants. Missing Yoast and
either WPSEO_PREMIUM_FILE or WPSEO_PREMIUM_VERSION leave presentation unchanged.
https://developer.wordpress.org/reference/hooks/plugins_loaded/

wp_loaded runs after provider integrations have registered. At priority 20 it
adds the documented-in-source public wpseo_submenu_pages filter at PHP_INT_MAX,
after Yoast's own late Brand Insights and upgrade callbacks. This also applies
when an editor's first accessible Yoast menu would otherwise be an upsell.
https://developer.wordpress.org/reference/hooks/wp_loaded/

admin_menu/network_admin_menu at PHP_INT_MAX use remove_submenu_page() for the
known Yoast parent and the redirects advertisement under tools.php. This is a
network/legacy navigation fallback. It never changes capabilities. The separate
Yoast network menu filter is marked internal and is not used.
https://developer.wordpress.org/reference/functions/remove_submenu_page/

admin_bar_menu at PHP_INT_MAX receives WP_Admin_Bar. remove_node() removes
specific advertising node IDs; unknown IDs are a no-op. This runs on existing
authenticated frontend toolbars too, without adding frontend assets.
https://developer.wordpress.org/reference/hooks/admin_bar_menu/
https://developer.wordpress.org/reference/classes/wp_admin_bar/remove_node/

The plugin-specific plugin_action_links and network_admin_plugin_action_links
filters receive action-link arrays. WP_HTML_Tag_Processor reads anchor hrefs;
wp_parse_url() compares the exact host yoa.st and path /1yb. Remaining keys and
HTML stay unchanged. It does not parse/rewrite complete pages.
https://developer.wordpress.org/reference/hooks/plugin_action_links_plugin_file/
https://developer.wordpress.org/reference/hooks/network_admin_plugin_action_links_plugin_file/
https://developer.wordpress.org/reference/classes/wp_html_tag_processor/
https://developer.wordpress.org/reference/functions/wp_parse_url/

admin_enqueue_scripts uses get_current_screen(). Only screen bases post, term,
edit-tags or IDs containing _page_wpseo_ enqueue one versioned local stylesheet
with wp_enqueue_style()/plugins_url(). On editors and the settings page only,
wp_enqueue_script() adds the dependency-free counters.js in the footer with
defer. Other Yoast pages receive no own JavaScript. No raw request parameters
are consumed.
https://developer.wordpress.org/reference/hooks/admin_enqueue_scripts/
https://developer.wordpress.org/reference/functions/get_current_screen/
https://developer.wordpress.org/reference/functions/wp_enqueue_style/
https://developer.wordpress.org/reference/functions/plugins_url/
https://developer.wordpress.org/reference/functions/wp_enqueue_script/

The main file uses WordPress's Requires Plugins header. WordPress handles normal
dependency activation. All plugin entry files stop when ABSPATH is absent.
There are no privileged state-changing endpoints or forms requiring nonces.
https://developer.wordpress.org/plugins/plugin-basics/header-requirements/
https://developer.wordpress.org/apis/security/
https://developer.wordpress.org/coding-standards/wordpress-coding-standards/php/
https://developer.wordpress.org/coding-standards/inline-documentation-standards/php/
https://developer.wordpress.org/plugins/wordpress-org/detailed-plugin-guidelines/

GitHub updates (since 1.2.0)

The Update URI header identifies https://github.com/rktsky/wpplugin.quiet-yoast.
The updater registers update_plugins_github.com independently of the Yoast
presentation guard. It serves the matching Update URI and the plugin's own
basename. WordPress compares the reported version to the installed header
and handles the update notice, download, installation and automatic update
preference.
https://developer.wordpress.org/reference/hooks/update_plugins_hostname/
https://developer.wordpress.org/reference/functions/wp_update_plugins/

wp_safe_remote_get() reads the public latest stable release from this fixed
endpoint with an anonymous, plugin-specific user agent:
https://api.github.com/repos/rktsky/wpplugin.quiet-yoast/releases/latest

The response must describe a published stable vMAJOR.MINOR.PATCH release with
its uploaded rktsky-quiet-yoast-MAJOR.MINOR.PATCH.zip asset at the exact versioned
GitHub download URL. The updater offers that ZIP as the package. It caches the
validated version in a network site transient for 15 minutes. Failed checks
cache an empty result for 5 minutes and report the installed version without
a package, keeping the native automatic update control available.
WordPress schedules the regular checks and installs packages through its
upgrader. Its external update hook runs after the WordPress.org update check.
https://developer.wordpress.org/reference/functions/wp_safe_remote_get/
https://developer.wordpress.org/reference/functions/set_site_transient/
https://docs.github.com/en/rest/releases/releases#get-the-latest-release
https://docs.github.com/en/rest/releases/assets#get-a-release-asset

The plugins_api filter supplies the plugin's version details dialog. It shares
the release cache and links to the GitHub changelog with escaped local HTML.
GitHub release notes are read on GitHub. Update and dialog metadata describe
the stable channel's minimums of WordPress 6.5 and PHP 7.4.
https://developer.wordpress.org/reference/hooks/plugins_api/

Presentation counter adapter (since 1.1.0)

ReadabilityAnalysis constructs upsellResults directly during render. The real
worker/Redux analysis result filters never receive this advertisement. The
analysis-report ContentAnalysis component counts the combined result array.
Settings features-section.js likewise counts its original features array.
CSS alone cannot correct these numeric text nodes. counters.js now corrects only
their displayed text, preserving the original assessment and provider state.

The adapter identifies fieldset.yst-group > button > h2 under the settings root
and the exact readability Problems button IDs. It verifies the native numeric
title against the number of direct UL>LI items. It excludes only a confirmed
advertisement row that the plugin's CSS actually hides, never an assessment
containing an AI upsell button or a whole accordion hidden by its ancestor.

It changes the unique title Text.data, preserving provider elements, SVG, event
handlers and React references. A WeakMap tracks the current native title text.
Native character-data writes are recorded even when their value equals our last
displayed correction. The observer disconnects for synchronous owned writes;
pending native records are drained first. This avoids repeated subtraction and
observer feedback loops. Batched microtasks refresh only known counters or
newly added counter markup in persistent owning roots; there is no polling.

When collapsing unmounts a list, prior exclusions are retained only if native
collapse is confirmed: aria-expanded=false for readability, or the settings
button's changed translated screen-reader label versus its observed open label,
with only the expected direct button remaining. A restructured/nested unknown
list restores the native text. No English-label or section-position guess is
used. Initially collapsed, unobserved lists retain native text until first
opened. Yoast 28.8's site-features store defaults all six sections open and does
not persist that slice, so ordinary initial route loading provides evidence.

A verified advertisement-only panel receives the owned attribute
data-rktsky-quiet-empty=true and is hidden. When real findings arrive, the marker
is removed and the panel returns. No result, stored score or licence flag is
changed. Unknown title/row structures retain native counts.

Maintenance

After a Yoast update, review the same source paths and repeat the functional and
visual checks before changing selectors. Unknown markup should remain visible
rather than removing real inputs. CSS hiding prevents rendering/focus exposure;
Yoast may still instantiate its own underlying promotional React components.
