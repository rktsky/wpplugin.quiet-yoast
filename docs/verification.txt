runtime passed 53 WordPress integration checks, five PHP/parser/guard
checks, eight native updater checks and 43 DOM assertions. The PHP 7.4
parser check covered the new updater class along with both existing PHP files.

provided release and package responses through WordPress's HTTP filter.

metadata, rendered its normal Plugins update action and opened the native
version-details dialog. The authenticated AJAX update used WordPress's own
upgrader to stream and install the ZIP. All nine files matched the release
source in the original active plugin directory, and the native automatic
update preference was preserved.

The suite also covers same-version checks, drafts and prereleases, invalid
tags and JSON, missing and incomplete assets, unexpected download origins
and a rate-limit response with backoff. Provider files remain unmodified.
The HTTP fixtures test the WordPress flow in isolation. The public release
endpoint and downloaded artifact are checked separately during publication.
The native scheduler was not run as an unattended automatic update.

Baseline 1.1.0 verification
2026-11-09

Executed integration checks

WordPress 7.1.4 and original free Yoast SEO 28.8 ran in WordPress Playground
3.1.62 with PHP 8.3.36/WASM and SQLite. Native WordPress activation, authenticated
admin requests and provider hook registration were used, not replacements for
WordPress functions. Fixtures blocked mail, external WP HTTP and scheduled cron.

53 integration assertions passed. They cover dependency/header recognition,
native activation, existing advertising menus before cleanup, removal and
preservation of unrelated destinations, administrator/editor roles, toolbar
nodes, repeated removal, asset scope, native plugin row actions and URL parser
negative controls, and native JavaScript registration. The counter script has
no dependencies, version 1.1.0, footer group 1 and defer; it is absent on other
Yoast pages and outside the intended editor/settings screens.
Similar hosts, paths, userinfo tricks, malformed/relative
URLs, plain text and non-string values remain untouched.

The representative anonymous frontend response was byte-identical with and
without the plugin. No own frontend CSS or JS and no SEO-output filter were
registered. This establishes output preservation for that fixture; it is not a
CPU benchmark or a claim about every third-party combination.

Own styles were absent on the WordPress dashboard, plugin list and post list.
They were present on Classic/block editor requests, Yoast settings and taxonomy
edit screens. The final PHP debug log was empty.

Five additional checks passed: native activation denied with the Yoast dependency
missing, PHP 7.4 syntax parsing of both owned PHP files, and simulated absent
Yoast / Premium FILE / Premium VERSION guards. The latter are constant-level
tests; no commercial Premium package was tested. PHP 7.4.34-dev/WASM was used for
these parser and guard checks, not for a complete WordPress/Yoast site run.

All 1949 original Yoast distribution files matched the downloaded archive
byte-for-byte. Test tools and original provider packages are outside this release.

Counter-specific regression checks

35 focused DOM regression assertions passed with jsdom 31.0.0 and the actual
admin.css/counters.js, without a computed-style shim. These are DOM fixtures,
distinct from the real WordPress browser checks above. They cover:

- Native count equal to the preceding corrected output; repeated updates;
  translated labels; replacement title nodes and SPA route remounts.
- Collapse/unmount/reopen using native aria-expanded or translated settings
  screen-reader labels; initial closed/no evidence; restructured or missing
  lists; aria-expanded-only and screen-reader-Text-only transitions.
- Real findings containing locked AI controls, available feature cards and
  unrelated links; mismatched row totals and ambiguous title markup.
- SVG, button and title Text node identity; advertisement-only panels hiding
  and restoring when real results return; no observer feedback while idle.

Review identified stale-cache cases when a list vanished without confirmed
collapse. The implementation now restores native counts in those unknown
states. Both additional accessibility-state observer regressions are covered.

Browser testing caught an additional modern footer variant and an incorrect
assumption that an analysis button ID identified the surrounding result list.
Both selectors were corrected and rechecked against the actual rendered DOM.

Known coverage limits

No production installation or deployment was performed. No performance timing
benchmark, WordPress.org submission, WordPress Plugin Check/PHPCS run, separate
MySQL matrix, real multisite site, commercial Premium package, Elementor live
session, older Yoast release, Firefox, native Safari, Edge or physical mobile
device was tested. Elementor selectors were source-reviewed only. Current CSS
uses :has(); older browsers may leave some promotional elements visible.

No broad compatibility certification is inferred from these checks. After a
Yoast update, repeat the settings/editor/browser checks before adjusting CSS.
